## Problem statement and completed scope

The problem is how to present prescribed mental-health skills with little reading, typing and decision-making while preserving the person's choice, ability to stop and access to support. **mello is a localhost coursework skills prototype for fictional demonstrations, not therapy, diagnosis, treatment or a human-monitored service.** It is not deployed or offered as mental-health support; clinical effectiveness is not evaluated.

The working Vue/FastAPI/SQLite application provides three fixed guides: **4–6 paced breathing**, six cycles at one second per count; **5–4–3–2–1 grounding**, five twelve-second sensory steps; and **STOP**, four fifteen-second steps. Their intended duration is sixty seconds. No written answer, questionnaire, model response or save request is required inside a sequence. Pause preserves the current position, Resume is explicit, and End is immediate. Completion does not force an exit or restart. Hidden pages and long scheduling gaps produce interrupted partial records rather than successful completion.

The current interface has a three-skill library, muted original coastal imagery, a sole bottom-right assistant popup, FAQs and source links, dated History and explicit settings. Accessibility options include higher contrast, larger text, simple reading font, text spacing, hidden scenery, reduced motion and step/phase/count/Off screen-reader updates. Keyboard focus, dialog Escape, redundant color/words and optional chatbot voice with visible text and Stop provide alternatives. Practices have no app-generated speech or tones. Display options are visit-only; Reduce motion takes precedence over remembered/reused animation without changing the rhythm. Real assistive-technology-user testing is not claimed.

## User state, saved history and model role

The application uses explicit choices and activity state, not inferred distress. SQLite stores session/content identity, dated messages with source/version metadata, events, available timing/outcomes, a remembered breathing cue and an explicit standard/brief reply profile. History distinguishes **Completed, Stopped, Interrupted and Not started**, shows last-chat dates, and supports review, reuse and deletion. A reused setting requires a new Start. Failed writes remain unconfirmed/Not saved with Retry and an unsaved-exit option; unknown recovered timing is not invented.

For a concrete fictional example, save Text only, Brief reminders and permission to use saved practice context; reload to restore them. A per-visit cue override does not overwrite the remembered setting. On a relevant question such as “Can I stop halfway?”, the local renderer selects brief reviewed copy and can refer to the actual latest saved **breathing** outcome/cue. Turning context off or resetting the profile removes that tailoring. Grounding/STOP records cannot be mislabeled as breathing history. SQLite is local and unencrypted, with one shared profile. This is activity history, not a biography, diagnosis, account system or clinical progress score. [Confirmed profile/message/database evidence](https://github.com/abn54/Health-App/blob/015631705d9d66595bb8d0865ea27d2e07998c83/docs/evidence/final-audit-oct31.json) and [current motion/reuse checks](https://github.com/abn54/Health-App/blob/015631705d9d66595bb8d0865ea27d2e07998c83/docs/evidence/accessibility-options-browser-nov1.json) document the examples and dates.

Current versions are **catalog `app-help-v7`, prompt `catalog-selector-v13`, renderer `profile-copy-v1`**. The optional local **qwen2.5:3b** model interprets the current question using authored topic context/examples and selects an allowed ID. The application validates the selection and renders reviewed text; raw profile/history are not sent to the model. Local rules apply explicit profile choices. The model cannot prescribe, invent skill steps, set timing, write preferences or navigate. Schema validation is not proof of semantic relevance.

Prepared/mock replies are default; live use requires explicit host configuration. The aggregate cap is at most **fifty provider attempts per host test session**, counting preloads, failed calls and retries, before returning to mocks. Deleting conversation data does not reset accounting. Independently worded questions cover reviewed everyday/app topics; suggestions are optional and unknown topics ask for clarification. Ordinary replies acknowledge the concern and offer choices rather than judgment. Explicit medical/therapist requests use reviewed limits without requiring inference. [Catalog/source copy](https://github.com/abn54/Health-App/blob/015631705d9d66595bb8d0865ea27d2e07998c83/shared/help-content.json) and [backend contract](https://github.com/abn54/Health-App/blob/015631705d9d66595bb8d0865ea27d2e07998c83/backend/main.py) are inspectable.

Bundled **Crisis support** remains accessible independently of a model, classifier or API result after the page loads, including during errors. Opening it during practice pauses first; returning does not automatically resume. A bounded phrase match can display fixed boundary copy but is a fallible interface cue: negations can match and indirect wording can be missed. It is not clinical assessment or proof of safety. Manual support never depends on a match; no location is inferred, no contact is initiated and no monitoring is implied.

## Relevant generated code and development evidence

The process failure occurred when Stop voice removed its focused button: focus fell to BODY and the popup-only Escape handler missed the event. The revised watcher waits for speech to become idle and Vue `nextTick`, then restores focus only if it escaped the still-open dialog. A document **capture** Escape listener receives the event even from BODY and calls the existing close/focus-return function. It does not seize focus from someone still typing or give the model navigation/timer authority. The recording shows failure→evidence→decision→retest; the [architecture](https://github.com/abn54/Health-App/blob/015631705d9d66595bb8d0865ea27d2e07998c83/docs/architecture.md) explains this and the unchanged monotonic skill clock.
